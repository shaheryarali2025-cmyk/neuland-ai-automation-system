NEULAND / BENJAMIN KATZ PROJECT — PROJECT UNDERSTANDING
=========================================================

1. PROJECT PURPOSE
------------------
This project was built to create an AI-agent + automation system for NEULAND, mainly for:
- Lead generation
- Lead qualification
- Duplicate prevention
- Google Sheets lead storage
- Monday.com CRM updates
- CRM monitoring and follow-ups
- Operations monitoring
- Content creation
- Telegram-based interaction with OpenClaw agents

The goal was not only to build n8n automations, but to make OpenClaw agents behave more like virtual assistants that Benjamin could use from Telegram.

Business context: NEULAND luxury ski / high-end travel, with both B2B and B2C lead-generation use cases.


2. MAIN TOOLS / PLATFORMS USED
------------------------------
OpenClaw
- Main AI agent/orchestrator
- Receives Telegram requests
- Chooses the right agent/workflow
- Triggers n8n webhooks
- Uses AGENTS.md/workspace context
- Returns final results to Telegram

Telegram
- Main interface used by Benjamin
- Separate groups/bots for Lead Gen, CRM, Operations, Content, etc.

n8n
- Main workflow automation engine
- Receives webhook requests from OpenClaw
- Calls Apify
- Qualifies leads
- Checks duplicates
- Routes leads
- Writes to Google Sheets
- Sends approved leads to Monday.com CRM
- Returns final response to OpenClaw

Apify
- Used as the lead-data / scraping source
- Returns people + company data
- Used for both B2B and B2C lead generation

Google Sheets
- Lead master sheets / working lead database
- Separate tabs for different ICPs and locations
- Used for duplicate checking and CRM approval status

Monday.com
- CRM system
- Used for pipelines, lead handoff, CRM updates, and follow-up monitoring

Hostinger VPS
- Hosts Dockerized OpenClaw + n8n services
- Main VPS: srv1817658.hstgr.cloud

7. DUPLICATE CHECKING
---------------------
Duplicate matching order:
1. LinkedIn URL
2. Email
3. Full Name + Company
4. Full Name + Title

Duplicate checks happen against:
- Existing Google Sheet rows
- Monday.com CRM

Important issue found:
One Telegram query sometimes triggered two n8n executions. Both could read the sheet before either finished writing, causing duplicate rows.

Root cause:
OpenClaw retried after short webhook/tool timeouts.

Rule/fix added:
- Trigger webhook exactly once per request
- exec timeout >= 300 seconds
- curl --max-time >= 300 seconds
- Poll the same running process
- Never launch a second webhook because of slow response


8. OPENCLAW WEBHOOK TIMEOUT ISSUE
---------------------------------
OpenClaw sometimes reported:
"Webhook timed out (exit code 28)"

Actual cause:
- n8n + Apify could take 2-3 minutes
- OpenClaw model-generated exec calls used short timeouts such as 10s / 15s / 30s
- Sometimes curl used --max-time 30
- The request was killed before n8n finished

AGENTS.md was updated to require:
- One webhook call only
- 300-second exec timeout
- 300-second curl timeout
- Poll same process
- No duplicate n8n execution on timeout


9. OPENCLAW GOOGLE SHEET MISUNDERSTANDING
-----------------------------------------
OpenClaw sometimes said it could not provide the Google Sheet URL because it did not have direct Google Sheets access.

That was incorrect for lead generation.

The n8n webhook response already returns:
- Destination sheet/tab
- Full sheet_url

AGENTS.md was updated so:
- "Find leads", "pull leads", "generate leads", etc. are always treated as new lead-generation requests
- OpenClaw should trigger the correct webhook
- Direct Google Sheets API access is not required to return sheet_url
- OpenClaw should report the URL exactly as returned by n8n


10. APIFY TARGETING ISSUE
-------------------------
Private Aviation initially returned unrelated companies such as publishing, landscaping, recruiting, automotive, etc.

The qualification logic correctly rejected them.

Actual cause:
A long raw Telegram/webhook keyword was being passed to Apify as one company keyword.

Fix:
Use focused fixed company_keywords arrays inside the Apify request.

13. LEAD COUNT BEHAVIOR
-----------------------
B2C workflow used:

fetch_count: Math.min(
  Number($('Webhook').first().json.body.count || 5),
  50
)

Meaning:
- count 10 -> process 10
- count 25 -> process 25
- count 50 -> process 50
- no count -> default 5
- above 50 -> capped at 50

Important:
50 processed does not necessarily mean 50 qualified.
Rejected, needs-review, and duplicate leads reduce the number actually added.

Benjamin's stated target:
- 50/day

Need to distinguish:
- 50 candidates processed/day
vs
- 50 final qualified/new leads/day

16. GMAIL + GOOGLE CALENDAR
---------------------------
Benjamin needs Gmail and Calendar for CRM management.

Observed issue:
- Google OAuth credential files existed
- Live API tests returned 401 UNAUTHENTICATED
- Access token was expired

Correct long-term behavior should be:
1. Detect expired access token
2. Use refresh_token
3. Get new access token
4. Save token/expiry
5. Retry API request
6. Only report disconnected if refresh itself fails

Random delays are not a solution.

Also check Google OAuth publishing status because testing-mode apps can have token lifecycle limitations.
